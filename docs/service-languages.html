Phase 1 baseline · 2026-07-11 · Companion to ARCHITECTURE.md · Status: Approved

1. Governing Principle: Two Languages, Not Five

Every language added to the stack multiplies CI pipelines, observability tooling, dependency scanning, hiring surface, and on-call knowledge. Themistra standardises on exactly two application languages:

  • Java 21 for every backend service — the team's core competency, and the JVM's maturity matches a product whose entire value is correctness of record.
  • TypeScript for the frontend, for infrastructure as code (AWS CDK), and for narrowly-scoped chain-adapter sidecars where the web3 ecosystem demands it.

A third language is only admitted through an ADR demonstrating that both existing languages materially fail the use case.

3. Rationale in Depth

3.1 Why Java everywhere on the backend — including the crypto service

The tempting alternative is Go for the watcher layer (classic concurrency story) or full TypeScript for the crypto service (richest web3 libraries). We reject both as primary choices:

  • Java 21 virtual threads removed Go's main advantage. Holding tens of thousands of provider websocket subscriptions no longer needs a special runtime.
  • The crypto service's hard parts are not chain I/O. They are quorum arbitration, per-chain finality policy, reorg-safe state, and the KMS signing path — audit-critical logic that benefits from the same typing, testing and review culture as the payment ledger it protects.
  • web3j and Tron's gRPC interface fully cover our launch chains (Ethereum, Tron). We pay the sidecar cost only when a chain actually demands it.

3.2 The TypeScript sidecar escape hatch

When a chain's Java tooling is inadequate, we add a minimal Node sidecar that speaks the chain's native SDK on one side and our internal adapter contract on the other. Rules:

  • Sidecars observe and translate only — no quorum decisions, no signing, no business state.
  • Each sidecar is one chain, one process, independently deployable and disposable.
  • The Java core treats sidecar output as just another provider answer, subject to the same 2-of-3 quorum.
Security consequence: everything that can cause a false attestation lives in one language, one review pipeline, one dependency-scanning regime. Sidecars can fail or lie without compromising an attestation, because they never hold quorum authority or key access.

3.3 Where we deliberately buy instead of build

Kafka (MSK), Postgres (RDS), key custody (KMS), immutable storage (S3 Object Lock) and edge protection (WAF/CloudFront) are managed services. Engineering hours go into the two things competitors cannot copy from a vendor: the quorum verification engine and the tamper-evident record.
