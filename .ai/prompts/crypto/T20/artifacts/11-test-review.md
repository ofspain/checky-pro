**Verdict:** The test suite covers every acceptance criterion and the named test from
`package.md` §8. The 11 existing tests are well-scoped and pass. Six gaps were found: one critical
(canary negative-proof), one high-priority lifecycle regression (new `destroy()` behavior added in
Phase 9 has no test), and four lower-priority coverage/robustness gaps.

A targeted run (`mvn -pl services/crypto test
-Dtest=KmsSignerTest,KmsSignerArchitectureTest,KmsSignerLocalStackIntegrationTest,KmsSignerSpringWiringTest`)
passed 11/11. As in Phase 8/9, ArchUnit emitted Java 26 bytecode-warnings (environment artifact,
project targets Java 21).

---

## 1. No negative-proof that the ArchUnit canary actually fails on a violation

- **Gap:** The plain-`@Test` canary (`shouldOnlyAllowAttestPathToInvokeKmsSignIsCheckedDuringStandardBuild`)
  asserts that the two ArchUnit rules pass on the *current, clean* codebase. It does not prove the
  canary would fail if a violation were introduced. Because `@ArchTest` fields are documented as not
  executing under this repo's Surefire setup, the entire R22/L11 guarantee rests on this single
  canary. A canary that is accidentally a no-op (e.g., importing the wrong package, swallowing
  exceptions, or checking empty classes) would not be detected by any existing test.
- **Why it matters:** This is the single most important test in the task. Without a negative-proof,
  we only know the rules pass on clean code; we do not know they can ever fail.
- **Suggested test:** Add a dedicated `KmsSignerArchitectureNegativeTest` that imports a deliberately
  violating class (or a small synthetic class set) and asserts each rule throws. Options:
  - A small Maven test-only source folder containing classes such as `com.themistra.crypto.watch.KmsSignerWatcher`
    and `com.themistra.crypto.other.UsesKmsSigner`, compiled only for the negative test and excluded
    from normal `mvn test`.
  - A runtime-generated bytecode class imported via ArchUnit's `ClassFileImporter` and passed to
    the rule's `check(...)` with `assertThatThrownBy(...).isInstanceOf(AssertionError.class)`.
- **Priority:** High.

## 2. `KmsSigner.destroy()` is not tested

- **Gap:** Phase 9 added `KmsSigner implements DisposableBean` with `destroy()` calling
  `kmsClient.close()`. No test verifies that `destroy()` actually closes the client, that it is
  idempotent, or that it is invoked by Spring on context shutdown.
- **Why it matters:** This is new production behavior added specifically to fix a resource-lifecycle
  finding. Without a test, a future refactor could remove the `implements DisposableBean`, change
  `destroy()` to no-op, or close the wrong field, and the build would stay green.
- **Suggested test:** Add to `KmsSignerTest`:
  ```java
  @Test
  void destroyClosesTheKmsClient() {
      signer.destroy();
      verify(kmsClient).close();
  }
  ```
  Optionally add an `ApplicationContextRunner` assertion in `KmsSignerSpringWiringTest` that the
  `KmsSigner` bean is an instance of `DisposableBean`.
- **Priority:** High.

## 3. `SignatureResult` package-private visibility is not locked by a test

- **Gap:** No test asserts that `SignatureResult` is package-private. If a future edit adds `public`
  to the record declaration, every other test would still pass.
- **Why it matters:** The frozen brief Phase 3 Finding #15 deliberately keeps `SignatureResult`
  package-private so a class outside `attest` cannot depend on it without tripping the boundary.
  Visibility is currently enforced only by convention and code review.
- **Suggested test:** Add a structural reflection test in `KmsSignerTest`:
  ```java
  @Test
  void signatureResultIsPackagePrivate() {
      assertThat(Modifier.isPublic(SignatureResult.class.getModifiers())).isFalse();
  }
  ```
- **Priority:** Low.

## 4. No regression test for startup fail-fast when AWS region is missing

- **Gap:** Finding #8's contingent verification was done with a standalone probe. The only test that
  touches region resolution (`KmsSignerSpringWiringTest`) *sets* `aws.region` to make wiring succeed.
  There is no test that clears the region and asserts the Spring context fails with
  `SdkClientException` during `KmsSigner` bean construction.
- **Why it matters:** The brief accepts Finding #8 only because verification showed AWS SDK v2 fails
  fast at `.build()` time. A regression in the AWS SDK version, in Spring bean construction order,
  or in how the `ApplicationContextRunner` replicates production startup could defer the failure.
- **Suggested test:** Add to `KmsSignerSpringWiringTest`:
  ```java
  @Test
  void kmsSignerBeanFailsFastWhenNoAwsRegionIsResolvable() {
      System.clearProperty("aws.region");
      contextRunner.run(context -> assertThat(context).hasFailed());
  }
  ```
  (Carefully manage system-property isolation so this test does not interfere with others.)
- **Priority:** Low.

## 5. Public constructor / `resolveKmsClient()` path is not exercised against a real endpoint

- **Gap:** `KmsSignerLocalStackIntegrationTest` signs through `KmsSigner` but uses the package-private
  test-seam constructor, injecting a pre-built `KmsClient`. The production path
  `public KmsSigner(KmsProperties, Clock) → resolveKmsClient()` is never executed against a real
  KMS-compatible endpoint.
- **Why it matters:** The test-seam constructor hides the real client-building logic. A bug in
  `resolveKmsClient()` (e.g., missing override configuration, wrong builder method, future SDK
  behavior change) would only surface in production or in `KmsSignerSpringWiringTest`, which does not
  actually call KMS.
- **Suggested test:** Add a LocalStack variant that constructs `KmsSigner` via its public constructor
  with the AWS SDK default provider chain pointed at LocalStack through env vars/system properties
  (`aws.region`, `aws.accessKeyId`, `aws.secretAccessKey`, `AWS_ENDPOINT_URL_KMS`), then signs and
  verifies as the existing test does.
- **Priority:** Low.

## 6. Exception-propagation test only covers `KmsException`

- **Gap:** `aKmsExceptionPropagatesUnwrapped` verifies only `KmsException` propagates. The brief
  says *any* `KmsClient.sign(...)` exception propagates uncaught, including `SdkClientException`
  (timeouts, region/credential issues), `IllegalArgumentException`, etc.
- **Why it matters:** A future change that accidentally wraps only `KmsException` but re-throws
  others, or that catches a supertype, would not be caught. A parameterized test makes the contract
  explicit.
- **Suggested test:** Replace or supplement the existing test with a parameterized version:
  ```java
  @ParameterizedTest
  @MethodSource("kmsExceptions")
  void anyKmsClientExceptionPropagatesUncaught(RuntimeException exception) {
      when(kmsClient.sign(any(SignRequest.class))).thenThrow(exception);
      assertThatThrownBy(() -> signer.sign(DIGEST)).isSameAs(exception);
  }

  static Stream<RuntimeException> kmsExceptions() {
      return Stream.of(
          KmsException.builder().message("kms unavailable").build(),
          SdkClientException.create("timeout"),
          new IllegalArgumentException("bad request"));
  }
  ```
- **Priority:** Low.
