## Files to create

### 1 · `contracts/api/oidc.yaml` (T20-D2, T20-D6) — CODEOWNERS review required

The token endpoint only. Shaped to match `auth.yaml` exactly: `openapi: 3.0.3`, `servers: [{ url: / }]`, an
`info.description` that states what the file is for and what it deliberately leaves out, `operationId` on the
operation, `security: []` because `checky-spa` is registered with `ClientAuthenticationMethod.NONE`.

- `paths./oauth2/token.post` — `operationId: exchangeToken`.
- **Request** — `required: true`, content `application/x-www-form-urlencoded`, schema `TokenRequest`:
  `grant_type` (enum of the single value `authorization_code`), `code`, `redirect_uri`, `client_id`,
  `code_verifier`, all five `required`, and **`additionalProperties: false`** — the contract itself is the first
  statement of AC4's "exactly five fields".
- **Response `200`** — content `application/json`, schema `TokenResponse`: `access_token`, `id_token`,
  `token_type`, `expires_in`, `scope`, all required. **No `refresh_token` is defined** (AC13, first of three
  pins). `additionalProperties` is **left open** here, deliberately and unlike the request: SAS owns what it
  sends, and a closed response schema would be this repository asserting something it does not control.
- **Response `400`** — `description` only, **no `content` schema**. SAS returns `error`/`error_description`
  there, and T20-D9 forbids that detail reaching anything. Giving it no schema means the generated client offers
  no typed accessor to a value the brief bans, so the ban is structural rather than a rule to remember.

The `info.description` records, in the file, that this contract exists because L6 requires a generated client for
every backend call and `auth.yaml` deliberately excludes the SAS protocol surface — so a reader who finds both
files understands why there are two rather than suspecting a mistake.

## Public API (signatures)

**`libs/ts/api-client/src/index.ts`**
```ts
export type { components as oidcComponents, operations as oidcOperations, paths as oidcPaths } from './generated/oidc';
export function createOidcClient(): ReturnType<typeof createClient<oidcPaths>>;
```
Built exactly like `createAuthClient` — `createClient<paths>({ baseUrl: '' })`, relative paths, no base URL, no
env key (L9, L10). The existing `auth` re-exports keep their unprefixed names, so no current import breaks.

**`frontend/src/auth/authorizeRequest.ts`**
```ts
export function redirectUri(): string;   // was private at :59-62; body unchanged
```

**`frontend/src/auth/codeExchange.ts`**
```ts
export type AuthorizationCodeGrant = { code: string; state: string };     // unchanged (T20-D8)
export type TokenResponse = { idToken: string; accessToken: string };
export async function exchangeAuthorizationCode(grant: AuthorizationCodeGrant): Promise<TokenResponse>;
```
`TokenResponse` gains `accessToken` and **nothing else**. `expires_in`, `scope` and `token_type` stay on the wire
until a task needs them: task 21 owns where the token lives and how long it is good for, and T20 returning a
field nobody reads is the kind of guess task 21 then has to undo. `state` stays on the grant and reaches no form
field (T20-D8, AC4).

## Private functions (`codeExchange.ts`)

| Function | Purpose |
|---|---|
| `storedCodeVerifier(): string \| null` | The guarded read (AC21). `sessionStorage.getItem` inside `try/catch`; a throw and a miss both give `null`; `''` normalizes to `null`, exactly as `idTokenNonce.ts:97-101` does for the nonce, so one absence value is tested rather than three. |
| `usableTokens(payload: unknown): TokenResponse \| null` | The wire boundary. Everything is `unknown` until checked: `null` unless the payload is an object whose `id_token` **and** `access_token` are both non-empty strings (AC12). This is T19's F1 lesson — a typed field is not a checked one. |
| `fail(): never` | The single opaque rejection (T20-D9, AC20). Throws one fixed `Error` with a fixed message that names no status, no `error`, no `error_description` and no response text. Every failure path calls it, so there is one rejection to reason about and one string to scan for. |

## Modules used

Frontend equivalents of the prompt's entity/repository/service sections.

- **Entities · none.** No persistence, no domain model. The only data is one request body and one response.
- **Repositories · `sessionStorage`, read-only.** One key, `AUTHORIZE_STORAGE_KEYS.codeVerifier`, read through
  the published constant and never spelled by hand. Nothing is written, deleted or cleared (AC9); the three L16
  items survive both paths, because deleting them is task 23's.
- **Services ·** `@themistra/api-client`'s `createOidcClient()` (the only transport), `authorizeRequest.ts` for
  `CLIENT_ID` and `redirectUri()`, and `CallbackScreen.tsx` as the only caller today. `idTokenNonce.ts` is
  untouched and simply receives a real token at last.

## Tests required

**`callbackValidatesNonceAndKeepsAccessTokenInMemory.test.tsx`** — the named suite, verifier half:

- **Verifier (AC1, AC2, AC21)** — stored and sent; proven over **two unrelated stored values** so nothing passes
  against a constant; absent; empty; and a `getItem` that **throws**, which must reject without mutating storage.
- **Wire (AC3, AC4, AC5, AC6)** — `POST`, relative `/oauth2/token`, the exact `Content-Type`, the **serialized
  body** parsed back to prove exactly five fields and no sixth, `redirect_uri` equal to what `redirectUri()`
  returns, and **no `Authorization` header and no client secret anywhere**. Observed with `stubBrowserFetch`
  (`generatedClientCompiles.test.ts:26-44`), sanctioned by the lint test's `ALLOWED` table (`:56`).
- **Response (AC12, AC13)** — the measured success shape; `400 invalid_grant`; 5xx; a network rejection; a 200
  with a non-JSON body; 200 missing `id_token`; 200 missing `access_token`; 200 with a non-string either. A 200
  that **does** carry `refresh_token` proves it reaches neither the return value nor anything else.
- **One outcome (AC11, AC20)** — each failure above drives the real screen and asserts the same copy, path,
  history action and query; then the distinctive `error_description` from the stubbed 400 is searched for in the
  DOM, the title, both storages, the console and the rejection's own message.
- **Ordering (AC8, AC14)** — a missing and a mismatched `state` still complete **no exchange**, now against a
  real transport rather than a seam; the nonce check still runs in place and still cannot be hoisted.
- **Non-leakage (AC10)** — no token value or segment in either storage, the URL, the DOM, the tab title or the
  console.
- **Source scans** — no absolute address, no `import.meta.env`, no hand-spelled storage key, no `refresh_token`,
  no `console.`, no module-level mutable state in `codeExchange.ts`. Each scan carries a synthetic violation
  proving it would catch one.
- **Controls** — every block carries one proving its assertion is reached, not merely satisfied. This package's
  recurring defect is an assertion compared against the constant it is testing; the controls exist for it.

## Execution order

Schema first, then the generated artefact, then the client, then the consumer, then the tests — so that nothing
is written against a shape that has not been generated yet.

1. **`contracts/api/oidc.yaml`.** The schema. Nothing downstream can be built before it exists.
2. **`package.json`'s `generate`**, then run it. `libs/ts/api-client/node_modules/.bin/openapi-typescript` is
   already installed, so this needs no install step. Inspect the generated `oidc.ts` **before** writing any code
   against it: whether `openapi-typescript@7.13.0` surfaces a form-encoded request body the way JSON ones appear
   is a fact to read off the output, not to assume. If it does not, STOP and log it — do not hand-write around it.
3. **`src/index.ts`** — `createOidcClient()` and the aliased type re-exports.
4. **`generatedClientCompiles.test.ts`** — `:69`, the drift case, the AC22 form-encoding case. Running it here
   proves the client works on the wire **before** any auth code depends on it, which is also the cheapest place
   to discover a content-type mistake (T20-D5's `===` trap).
5. **`authorizeRequest.ts`** — export `redirectUri()`. One keyword, run the existing suites.
6. **`codeExchange.ts`** — the real exchange: guarded read, body, call, `usableTokens`, `fail()`.
7. **`CallbackScreen.tsx`** — the `:112-115` comment correction (OQ-4). No behaviour change.
8. **`lintRejectsHandWrittenBackendFetch.test.ts`** — the `ALLOWED` entry.
9. **The named test**, in Phase 10's full form; Phase 6 writes only what it needs to see the code work.
10. **Whole suite + `tsc` + `oxlint`**, exit codes checked, not counts.

**Commit before any mutation run.** The harness reverts with `git checkout --`, and uncommitted test edits are
destroyed silently — it has already cost this package 24 cases across T14 and T15.
