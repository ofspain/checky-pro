## Commit message

```
feat(frontend): nest the authenticated routes in a shell that can sign out

R28 has two clauses and only one of them was built. Tasks 40 and 41 made
an unauthenticated arrival redirect to the sign-in start; what a SESSION
renders was a gate with eleven paths hanging straight off it, ten of them
rendering an empty document. A shell wrapped every route and had since
task 1, so the task statement was already literally true read that way -
what did not exist was any layer BETWEEN the gate and the eleven paths,
and L12 forbids tasks 43 onward from replacing the Phase 1 shell to make
one.

This is that layer: one pathless route inside RequireSession, holding the
eleven paths as children, rendering a banner landmark above <Outlet />.

The owner closed OQ-T42-2 during the brief, so the chrome carries the
sign-out affordance - which makes this the FIRST CALLER the sign-out path
has ever had. endSession() was built in task 36 and never called;
api/crossTabSignOut.ts was built in task 39 and never installed. Seven
consecutive tasks shipped a mechanism nobody could reach (OQ-T36-5). The
control calls endSession() once, and the layout installs the cross-tab
listener once per mount and closes it on unmount, so R19 and R22's last
clause are satisfied by a journey rather than by a mechanism.

A receiving tab renders RedirectToSignIn in place of <Outlet /> rather
than navigating itself: the gate is a read at render and is this layout's
parent, so it cannot re-ask its question, and the destination, the return
target and the replace-vs-push decision all stay with the component task
41 built to own them.

Banner is a ninth primitive, which app/ui/index.ts invited and priced
("a ninth must be added deliberately"). The chrome needs a landmark for a
keyboard user to find the control, rule 2 says a role is set INSIDE a
primitive, and <header>'s banner mapping is conditional on its ancestry -
so the alternative was not a cheaper landmark, it was no landmark. Its
suite asserts the ancestry rather than the tag.

Measured, not asserted: 31 mutation rows, 28 of 29 regressions killed, the
canary killed, one row unfalsifiable as predicted and one survivor. The
survivor is TE28, which inverts the receiving tab's two statements and goes
undetected because React batches them - so the comment claiming that order
was a criterion was corrected rather than the row relabelled.

Three limits are pinned by cases that must FAIL when someone closes them:
a tab on a public path does not react to a sibling's sign-out (OQ-T42-5),
the banner has no accessible name, and the ten element-less paths render
chrome over an empty document until their own tasks run (OQ-T42-3).

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```
