## Gaps

### 1. AC2 is not exercised end-to-end
**Gap ·** Case 4 asserts the `build` script string starts with `pnpm run lint`. It does not actually run `pnpm -C frontend build` with a violating file present to prove that `tsc` and Vite never execute. The manifest notes this was shown manually in Phase 6 but is not repeated in the automated suite.  
**Why it matters ·** AC2 is a behavioural guarantee: a violation must fail the build before type-checking and bundling. A script-string check cannot detect a regression where `&&` precedence, shell escaping, or script ordering changes in a way that still looks correct but no longer short-circuits.  
**Suggested test ·** Create a disposable copy of the `frontend/` package structure in a temp directory (or use a temp file under `frontend/src` that is removed in `finally`), write a `fetch(...)` violation, run `pnpm run build` (or the equivalent `pnpm -C frontend build`), and assert: (a) exit code is non-zero; (b) the output contains oxlint diagnostics; (c) no `dist/` directory is produced and no `tsc`/`vite build` output appears. Clean up the violation afterwards.

### 2. `document.defaultView.fetch` is not covered
**Gap ·** The manifest lists `document.defaultView.fetch` as a residual bypass not covered by design. It is a common alias for `window.fetch` in DOM-heavy code.  
**Why it matters ·** It is a one-line bypass that does not require metaprogramming or alias tracking. A developer could use it intentionally or copy code that does.  
**Suggested test ·** Add `document.defaultView.fetch` to the property list in `.oxlintrc.json` and add a corresponding fixture in case 1. If oxlint does not recognise `document.defaultView` as an object alias for `window`, document it as a residual bypass alongside `const w = window`.

### 3. `window['XMLHttpRequest']` is not explicitly fixture-tested
**Gap ·** Case 1 includes `globalThis['XMLHttpRequest']` as a bracket-access form, but not `window['XMLHttpRequest']` or `self['XMLHttpRequest']`. Case 6 verifies the rule entries exist for all seven objects, but the fixture coverage is asymmetric.  
**Why it matters ·** Bracket access can be generated by bundlers or obfuscators. Symmetric fixtures ensure the rule works for every configured object.  
**Suggested test ·** Extend the `it.each` in case 1 to include `window['XMLHttpRequest']` and `self['XMLHttpRequest']` (or one representative object other than `globalThis`).

### 4. No test that the running oxlint binary matches the pinned version
**Gap ·** Case 4 checks `package.json` for `"oxlint": "1.87.0"`. It does not run `oxlint --version` and assert the output matches. A stale or globally installed binary could diverge from the lockfile.  
**Why it matters ·** The rule behavior (especially directive handling and category defaults) is version-specific. A version mismatch could silently change lint results.  
**Suggested test ·** Add a lightweight case that runs `frontend/node_modules/.bin/oxlint --version` and asserts it starts with `1.87.0`.

### 5. No test that the directive scan ignores its own test literals
**Gap ·** The test builds directive patterns from string parts so the file doesn't match its own scan. There is no explicit assertion that the scan would fail if a real directive were present in `src/`. The mutation break appends a directive to `AppShell.tsx` and expects case 7 to fail, which indirectly validates this.  
**Why it matters ·** A subtle regex bug could make the scan miss real directives or false-positive on its own construction.  
**Suggested test ·** Keep the existing mutation break, and add a focused negative fixture: a temp file containing `// oxlint-disable-next-line no-restricted-globals` scanned by the same regex should produce a match.

### 6. No test for `XMLHttpRequest` used as a type only
**Gap ·** `no-restricted-globals` may or may not flag `const xhr: XMLHttpRequest`. The behavior is unspecified. If it is flagged, legitimate type annotations would need an escape; if it is not flagged, it is a minor bypass.  
**Why it matters ·** Future screens may reference `XMLHttpRequest` only for typing (e.g., mocking). Knowing the rule's behavior avoids surprises.  
**Suggested test ·** Add an allowed fixture `const _xhr: XMLHttpRequest` and assert exit 0, or a banned fixture `const _xhr: XMLHttpRequest = new XMLHttpRequest()` and assert exit 1. Record the behavior.

### 7. No test for `fetch` in a `declare global` augmentation
**Gap ·** App code could augment the global scope and reference `fetch` inside a `declare global` block. This is unlikely but not impossible for polyfill declarations.  
**Why it matters ·** A global augmentation that references `fetch` could be a backdoor. The rule should either flag it or be documented as allowed.  
**Suggested test ·** Optional: add a fixture with `declare global { const fetch: typeof globalThis.fetch; }` and determine whether oxlint flags it. Document the result.

## Non-gaps (acknowledged, no change needed)

- **Residual bypasses (`const w = window`, `Reflect.get`, `this.fetch`).** Correctly documented as limits of name-based lint.
- **No end-to-end `build` run in the suite.** Partially mitigated by the script-string assertion and the manual Phase 6 check, though finding 1 above recommends automating it.
- **Test file constructs directive patterns from string parts.** An acceptable way to avoid self-matching.
- **Case 6 rule-shape assertion.** Strong protection against config drift.
- **Case 7 directive scan.** Good defence against inline disable comments.

---

## Summary

The Phase 10 test manifest is thorough: it covers 19 banned forms, 4 allowed forms, the real `src` lint, script ordering, the `.eslintignore` bypass, the exact config shape, and inline directives. The main gap is that AC2 is not exercised end-to-end: the suite never runs `pnpm build` with a violation to prove that `tsc` and Vite are skipped. Adding that, plus `document.defaultView.fetch` coverage, symmetric `XMLHttpRequest` bracket fixtures, and a binary-version check, would make the suite a complete gate for L6.
