## Commit message

```
feat(frontend): give /app/home a screen and move focus to it on arrival

/app/home already resolved, already sat behind RequireSession, and was
already where returnTarget sends a completed sign-in when no allowlisted
target was remembered (L1). It rendered nothing. A sign-in therefore
finished on a blank document with focus on <body>, which tells a
screen-reader user that nothing happened.

HomeScreen is twelve lines: a Screen landmark, a Heading, a Text, and one
effect that focuses the heading on mount. Both strings are catalogue
entries, so the copy is the owner's to rewrite without touching a
component.

THE DECISION THIS TASK TURNED ON. The screen needs a focusable heading,
and the obvious route was a tabIndex prop on Heading - one task after
T173's ui/index.ts froze rule 2: "No primitive accepts the attribute that
is its own contract. role, aria-live, tabIndex, type="button" and the
heading level are set inside." The rule's own text prescribes the
alternative, so tabIndex={-1} is set INSIDE Heading and its props type is
still { children: ReactNode }. No prop, no type widening, no rule
amendment, no ninth primitive - and every <h1> in the SPA gains the focus
target for free. A rule relaxed by its first customer was never a rule.
tsc enforces it: a consumer passing tabIndex fails the real build that an
existing end-to-end case runs.

TWO DEFERRALS THAT WERE NEVER BLOCKED. OQ-T41-2 deferred the end-to-end
proof of the post-sign-in landing to task 42, and this task's own freeze
deferred it again as OQ-T174-4. The case already existed. loginChallenge...
held a pin that drove a real callback through a real exchange onto
/app/home and asserted the landing rendered nothing, announced nothing and
stranded focus on <body> - with a note telling whoever built the screen to
delete it and assert the real target. It had been failing by design for
eleven tasks. It is now discharged and asserts focus on this heading. A
deferral is a claim, and it deserves a grep.

The screen opened a hole and closes it. Before this change a .focus() added
to any screen was inert, because no <h1> was focusable; Heading changed that
for all four screens at once. A guard mounts SignInScreen, SignedOutScreen
and CallbackScreen and asserts each leaves focus on <body> - the sign-in
screen especially, where a visitor who tabbed to the button and came back
would otherwise be thrown out of position.

Five instruments grew where the freeze named three, each grown rather than
loosened: T33's AC11 became the exact list [HOME_PATH], so it fails again at
the next screen rather than tolerating any number of them. The render-site
sweep was structurally BLIND to this screen - it finds files by lowercase JSX
tag and HomeScreen has none - so it now derives the list from barrel imports
in both directions, with a control that plants a non-importing file.

Tests: 29 cases in the named suite, 1862 of 1863 passing in the whole suite
(the known host oxlint case), 21 of 21 mutants killed with none broken.

Specification: task 174; R28, R22, R20, R29; L1, L11, L12, L16; T173 §6e and
ui/index.ts rule 2.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```
